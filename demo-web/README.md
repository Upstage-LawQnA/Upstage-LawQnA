# 민원을 잇다 — 시연 서비스

지역을 고르고 평소 말투로 물으면, 그 지역 자치법규에서 근거 조항을 찾아 쉬운 말로 답하고,
조례로 답하기 어려운 질문은 근거와 쟁점을 묶어 담당 공무원에게 넘기는 시연용 웹 서비스입니다.

채점용 API(`POST /ask`, 서울특별시 조례 6종)는 저장소 루트(`main` 브랜치)에 있고, 이 폴더는 그와 별개입니다.

## 실행 방법

Python 3.11 이상에서 확인했습니다. Windows에서 한글이 깨지면 `python` 대신 `python -X utf8`을 쓰세요.

```bash
cd demo-web
pip install -r requirements.txt
cp .env.example .env        # Windows: copy .env.example .env
# .env에 UPSTAGE_API_KEY(Upstage 콘솔)와 LAW_OC(법제처 OPEN API 인증값)를 넣습니다
python -X utf8 -m uvicorn app:app --host 127.0.0.1 --port 8001
```

브라우저에서 http://127.0.0.1:8001 을 엽니다.

- 처음 묻는 지역·조례는 법제처에서 원문을 받아 색인하므로 시간이 걸립니다. 받은 원문과 색인은 `data/cache/`에 저장되어 다음부터 빨라집니다.
- `.env`, `data/cache/`, `data/tickets.json`(접수된 민원), `logs/`는 저장소에 올리지 않습니다.

## 화면

| 화면 | 하는 일 |
|---|---|
| 질문하기 | 16개 시·도 중 지역을 고르고 질문 → 단계 표시(질문 분석 → 조례 검색 → 답변 작성) → 답 · 근거 조항 · 시행일 · 원문 링크 · 담당 부서 |
| 조례 상세 | 홈의 '최근 시행된 조례'에서 이동. 제·개정 이유, 조항 목록, 그 조례 안에서만 찾는 질문창 |
| 지역 비교 | 같은 질문을 2~4개 지역으로 비교. 목록 또는 지도로 지역 선택 |
| 민원 작성 | 담당자 문의(질문 · AI 답변 초안 · 근거 조항 · AI 정리 쟁점) |
| 공무원 모드 | 민원함, 근거 묶음 확인, 회신문 작성 |

## 처리 단계와 Upstage 모델

| 단계 | 하는 일 | 모델 · 도구 |
|---|---|---|
| 질문 분석 | 5분류(조례 질의 · 국가 법령 질의 · 사업·운영 문의 · 현장 민원 · 건의·제안), 검색어, 낱말 입력을 완전한 질문으로, 개인정보 가리기 | `solar-pro4` |
| 수집 | 법제처 OPEN API로 선택 지역 자치법규 검색 → 관련 조례 6개 재선택 → 원문 XML을 조·항·호로 분리. 민원 신청일 기준 과거 버전·부칙 | 법제처 OPEN API, `solar-pro4`, `solar-embedding-2-passage` |
| 문서 파싱 | 요금·감면·기준 별표(hwp·pdf)를 표 구조로 변환해 근거로 사용 | Upstage Document Parse |
| 검색 | 질문 재작성, 의미 0.9 + 키워드(Kiwi 형태소 BM25) 0.1, 근거 8개 + 같은 조 다른 항 · 조문 속 참조 · 정의 조항 | `solar-embedding-2-query`, `solar-pro4` |
| 답변 생성 | 결론·인용 원문을 먼저 설계 → 후보 답 2~4개 → 결론·근거 조가 같은 답이 2개 이상일 때만 채택. 근거는 조항 라벨 중에서만 선택 | `solar-pro4` (추론 모드) |
| 검증 | 근거 충실성 · 질문 밖 문장 · 네·아니요 최종 논리 점검, 인용 원문·숫자 대조. 통과 못 하면 '확인 불가'. 세부를 시장이 정한다고 맡긴 경우 위임 조항으로 안내 | `solar-pro4` + 규칙 검사 |
| 유형 · 연결 | 답변 유형(간단 · 복잡 · 회색지대 · 담당자 확인 필요 · 자치구 확인 필요 · 국가 법령 확인 등), 담당 부서, 공무원용 쟁점. 국가 법령·사업 운영 질문에 조례로 답하면 민원함에 자동 등록 | `solar-pro4` |

Upstage `groundedness-check` 모델은 지원 종료되어 근거 충실성 판정은 `solar-pro4`로 대체했습니다.

## 파일

| 파일 | 역할 |
|---|---|
| `app.py` | 웹 서버(FastAPI). `/api/ask/stream`, `/api/compare`, `/api/tickets`, `/api/law`, `/api/recent`, `/api/regions` |
| `service.py` | 질문 분석, 답변 유형, 담당 부서, 민원(티켓), 지역 비교 |
| `corpus.py` | 지역별 자치법규 수집 · 과거 버전 · 부칙 · 별표 · 정의 조항 |
| `rag.py` | 검색 · 답변 설계 · 후보 답 합의 · 검증 · 위임 조항 답변 |
| `upstage.py` | Upstage API 호출(채팅 · 임베딩 · Document Parse) |
| `config.py` | 모델명 · 근거 수 · 추론 모드 등 설정 |
| `build_index.py`, `fetch_ordinances.py`, `parse_annex.py` | 조문 조각 만들기, 법제처 원문 파싱, 별표 변환 |
| `static/index.html` | 화면 |
| `data/` | 서울특별시 조례 6종 기본 색인(원문 XML · 조각 · 벡터 · 별표 표) |

## 출처

- 자치법규: 법제처 국가법령정보센터 OPEN API
- 지도(`static/region_map.json`): 통계청 SGIS 행정동 경계 2026-10-01 기준(vuski/admdongkor, CC BY 4.0)을 시·도 단위로 합쳐 단순화

## 한계

- 답변까지 검증 단계가 많아 질문당 수십 초가 걸리고, 동시 사용이 몰리면 API 호출 한도에 걸릴 수 있습니다.
- 정확도는 서울특별시 민원으로만 측정했습니다.
- 민원 저장은 JSON 파일이고 로그인·권한 기능은 없습니다(시연 수준).
- AI의 답은 참고용이며 공식 답변이 아닙니다.
